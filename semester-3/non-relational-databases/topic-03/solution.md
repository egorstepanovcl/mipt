# Самостоятельное задание по теме 3

**Дисциплина:** Нереляционные базы данных

**Тема:** Базы данных «ключ-значение»

---

## Техническое задание 1. Система кэширования для блога

**Выбранная технология:** Redis

**Обоснование**

Redis хорошо подходит для реализации системы кэширования, так как в основном работает с данными в оперативной памяти. Это обеспечивает минимальную задержку при обращении к данным.

Redis часто используется для кэширования и позволяет хранить часто запрашиваемые данные, например результаты запросов к основной базе данных, HTML-страницы и JSON-ответы.

Для управления временем хранения данных можно использовать механизм TTL. Он позволяет задать время жизни ключа, после которого Redis автоматически удалит данные из кэша.

Поскольку по условиям задания потеря данных кэша при перезапуске допустима, Redis можно использовать именно как быстрое промежуточное хранилище между приложением и основной базой данных.

Таким образом, Redis подходит для данного проекта благодаря высокой скорости работы, простоте модели «ключ-значение» и возможности эффективно использовать его в качестве кэша.

## Техническое задание 2. Сервис для аналитики и рекомендаций в реальном времени

**Выбранная технология:** Redis

**Обоснование**

Redis подходит для обработки данных в реальном времени, поскольку кроме обычных пар «ключ-значение» поддерживает несколько типов структур данных.

Для разных требований задания можно использовать:

* строки — для хранения и изменения счётчиков;
* списки — для хранения последних действий пользователей и организации очередей;
* отсортированные множества — для хранения рейтингов;
* потоки Redis Streams — для хранения и обработки событий.

Redis обеспечивает высокую скорость работы за счёт хранения данных в оперативной памяти.

Для обработки нескольких связанных операций Redis также поддерживает транзакции, которые позволяют выполнять группу команд атомарно.

Redis Streams можно использовать для событий, поскольку эта структура действует как журнал событий и обеспечивает более надёжную обработку сообщений, чем обычный Pub/Sub.

Таким образом, Redis подходит для сервиса аналитики и рекомендаций благодаря высокой производительности, поддержке различных структур данных, атомарных операций и механизмов обработки событий.

## Техническое задание 3. Хранилище пользовательских профилей и настроек для SaaS-приложения

**Выбранная технология:** Amazon DynamoDB

**Обоснование**

Amazon DynamoDB подходит для хранения пользовательских профилей и настроек SaaS-приложения.

DynamoDB является полностью управляемым облачным сервисом AWS. Это соответствует требованию минимального администрирования, поскольку пользователю не требуется самостоятельно управлять серверами базы данных.

DynamoDB рассчитана на высокую масштабируемость и производительность и предназначена для работы с большими объёмами данных и высокой нагрузкой.

Система позволяет выбирать между моделями Eventual Consistency и Strong Consistency в зависимости от требований к производительности и актуальности данных.

Кроме того, DynamoDB поддерживает вторичные индексы. Благодаря этому данные можно искать не только по основному ключу, но и по отдельным атрибутам внутри значения.

Модель «ключ-значение» позволяет хранить в качестве значения различные данные пользовательского профиля, например имя, email, настройки, тарифный план и предпочтения.

Таким образом, DynamoDB подходит для данного проекта благодаря высокой масштабируемости, производительности, управляемой облачной модели и поддержке вторичных индексов.
