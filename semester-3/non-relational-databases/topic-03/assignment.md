## Техническое задание 1. Система кэширования для блога

**Название проекта:** High-Performance Blog Caching System

**Описание**

Разработать и внедрить систему кэширования для высоконагруженного новостного или блогового портала. Основная цель — снизить нагрузку на основную базу данных (например, PostgreSQL) и ускорить доставку контента пользователям.

**Требования**

* **Функциональность:** система должна кэшировать результаты запросов к базе данных, включая HTML-страницы, JSON-ответы API и популярные статьи.
* **Производительность:** требуемая задержка при чтении из кэша — менее 1 миллисекунды.
* **Надежность:** допустима потеря данных в кэше при перезапуске сервера (кэш может быть заполнен заново).
* **Масштабируемость:** система должна поддерживать простое горизонтальное масштабирование путем добавления новых узлов.
* **Простота:** реализация должна быть максимально простой и легковесной, без сложной логики.

## Техническое задание 2. Сервис для аналитики и рекомендаций в реальном времени

**Название проекта:** Real-Time Analytics and Recommendation Service

**Описание**

Создать бэкенд-сервис для обработки данных в реальном времени. Система должна собирать данные о действиях пользователей (клики, просмотры, оценки) и на их основе генерировать персональные рекомендации и аналитические отчеты.

**Требования**

* **Функциональность:** система хранить счётчики просмотров, списки последних действий, рейтинги и очереди событий.
* **Производительность:** обработка данных должна происходить с минимальной задержкой. Требуется поддержка сложных операций, таких как атомарное инкрементирование счётчиков, работа со списками и отсортированными множествами.
* **Надежность:** часть данных (например, счётчики) должна быть персистентной и не теряться при сбоях.
* **Масштабируемость:** система должна легко масштабироваться для обработки миллионов событий в секунду.

## Техническое задание 3. Хранилище пользовательских профилей и настроек для SaaS-приложения

**Название проекта:** User Profile and Configuration Management Service

**Описание**

Разработать надёжное и масштабируемое хранилище для пользовательских профилей, настроек и параметров подписки в SaaS-приложении. Основная цель — обеспечить высокую доступность и производительность при масштабировании до миллионов пользователей.

**Требования**

* **Функциональность:** хранение структурированных и полуструктурированных данных (имя, email, тарифный план, предпочтения, история подписки).
* **Надежность и доступность:** система должна обеспечивать очень высокую доступность (99.99%) и быть устойчивой к сбоям.
* **Производительность:** низкая задержка при чтении и записи, независимо от объёма данных.
* **Управляемость:** требуется минимальное администрирование и отсутствие необходимости управлять серверами, патчами или резервным копированием.
* **Гибкость схемы:** данные могут иметь разный набор полей для разных типов пользователей.
