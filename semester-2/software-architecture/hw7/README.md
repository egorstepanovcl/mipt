# Домашнее задание 7. Аутентификация

## Информация о выполнении задания

Задание выполняется **индивидуально**.

## Цель задания

Научиться реализовывать аутентификацию между несколькими микросервисами.

## Условия

В рамках этого задания вам необходимо создать два микросервиса, один из которых будет аутентифицировать пользователя и выдавать ему JWT-токен, а второй будет принимать от пользователя сообщение и класть его в базу данных от его имени, проверяя перед этим корректность этого JWT-токена.

## Шаги выполнения

1. Создайте **приложение для аутентификации**, которое будет регистрировать и аутентифицировать пользователей и соответствовать следующим условиям:

   - Приложение должно будет работать с одной таблицей базы данных `users`, имеющей следующую структуру: `id`, `email`, `password`. В поле `password` должны храниться надёжно захэшированные пароли пользователей.
   - Приложение должно принимать POST-запрос на регистрацию пользователя, в котором в JSON-формате должны содержаться `email` и пароль. В ответ на этот запрос приложение должно возвращать ошибку, если `email` неверный, уже существует или пароль небезопасный. Если всё перечисленное корректно, приложение должно возвращать пустой ответ с кодом `201`.
   - Приложение должно также принимать POST-запрос аутентификации с `email` и паролем в формате JSON и проверять их корректность. Если некорректен `email` или некорректен пароль, должен возвращаться пустой ответ с кодом `401`. Если корректны, то ответ с кодом `200` и JWT-токеном, содержащим `user_id` и срок действия.

2. Создайте **приложение для публикации постов**, которое в POST-запросе будет:

   - Принимать текст сообщения в виде JSON-объекта с ключом `message` и JWT-токеном в заголовке:
     ```
     Authorization: Bearer <token>
     ```
   - Проверять подпись переданного токена и срок его действия.
   - Если всё корректно, то сохранять сообщение в таблицу `messages`, содержащую поля `id`, `user_id`, `time`, `message`. В поле `time` должны быть дата и время сохранения сообщения. В ответ возвращать код `201` и пустой ответ.
   - Если подпись токена некорректна, возвращать пустой ответ с кодом `400`.
   - Если срок действия токена истёк, возвращать пустой ответ с кодом `401`.

3. Пропишите для обоих приложений **Dockerfile**. Соберите и запустите контейнеры и приложения при помощи **docker compose**. Базу данных поместите в третий контейнер.

4. Создайте в **Postman** три запроса — на регистрацию пользователя, аутентификацию и создание сообщения с отправкой JWT-токена. Проверьте, что всё работает корректно. Исправьте ошибки, если они будут.

## Формат сдачи и отправка задания

- **Коды обоих приложений.**
- **Видеодемонстрация** работы регистрации, аутентификации и отправки сообщения. На видеодемонстрации должно быть видно, как вы отправляете в Postman запросы на регистрацию, аутентификацию и создание сообщения. Должны быть видны все параметры и тела запросов, а также все заголовки и тела ответов. Должны быть показаны как все верные запросы и ответы, так и все перечисленные в задании ошибочные варианты ответов.

## Критерии оценивания

| Критерии | Баллы |
| --- | --- |
| Регистрация работает корректно при корректном запросе: пользователь появляется в базе данных | 1 |
| Пароль хэшируется безопасным способом (например, bcrypt) | 1 |
| Регистрация не срабатывает при отправке пользователя с уже зарегистрированным email | 1 |
| Регистрация не срабатывает при отправке пользователя с некорректным email | 1 |
| Аутентификация работает верно при верном сочетании логина и пароля | 1 |
| Аутентификация не работает, если указан неверный email | 1 |
| Аутентификация не работает, если указан неверный пароль | 1 |
| Сообщение отправляется, если подпись токена верная и срок действия его не истек | 1 |
| Сообщение не отправляется, если подпись токена некорректна | 1 |
| Сообщение не отправляется, если срок действия токена истек | 1 |

- **Максимальный балл за задание:** 10 баллов
- **Как проверяется:** в течение недели после дедлайна
