# Домашнее задание 3. Проведение юнит-тестов с помощью PyTest

## Информация о выполнении задания

Задание выполняется на оценку индивидуально.

## Содержание задания

### Цель задания

Применить инструменты PyTest (фикстуры, параметризацию, мок-объекты при необходимости)
и написать тесты, учитывая как позитивные, так и негативные сценарии.

### Условия

- Напишите минимум **2 позитивных и 2 негативных теста** для каждой функции
  (всего 5 функций), используя PyTest (можно использовать фикстуры и параметризацию).
- При необходимости примените mock-объекты, например, для внешних вызовов БД,
  отправки почты.
- Выберите сервис для тестирования (**Booking-сервис** или **Task Manager**).
- Создайте проект (или несколько файлов) для тестов.
- Напишите PyTest-тесты для 5 указанных функций.
- Оформите так, чтобы можно было запустить тесты командой `pytest` и увидеть результат.
- *(Опционально)* Добавьте README или комментарии: как запускать тесты и что именно
  проверяется в каждом.

## Алгоритм проведения юнит-теста

### Booking-сервис

1. **`calc_price(base_price: float, discount: float, count: int) -> float`**
   - Рассчитывает итоговую сумму за `count` билетов с учётом базовой цены и возможной
     скидки.
   - Учесть граничные случаи: количество билетов = 0, отрицательная скидка, большие
     числа.

2. **`check_availability(event_id: int, seats_requested: int) -> bool`**
   - Проверяет наличие свободных мест.
   - При нехватке мест возвращает `False`, иначе — `True`.
   - Можно замокать вызов БД или внешнего метода, чтобы возвращать текущее количество
     оставшихся билетов.

3. **`apply_promo_code(order_id: int, promo_code: str) -> bool`**
   - Применяет промокод к заказу, если он действителен.
   - Проверка на истёкший/невалидный промокод, исчерпанный лимит использования.
   - Тесты могут включать моки или заглушки для обращения к репозиторию промокодов.

4. **`generate_booking_ref(user_id: int, event_id: int) -> str`**
   - Генерирует уникальный код/референс бронирования на основе идентификаторов
     пользователя и события.
   - Можно проверить формат (например, `BOOK-<user_id>-<event_id>-<random_suffix>`).
   - Учесть уникальность результата при повторных вызовах.

5. **`send_notification_email(email: str, booking_details: dict) -> bool`**
   - Отправляет уведомление на почту при успешном бронировании/оплате.
   - Использовать мок-объект отправки почты (SMTP или любой mail-сервис).
   - Проверить, что функция возвращает `True` при успехе и обрабатывает исключения
     (например, недоступность почтового сервера).

### Task Manager

1. **`create_task(project_id: int, title: str, deadline: datetime) -> int`**
   - Создаёт задачу в рамках проекта, возвращает `task_id`.
   - Проверить валидные и невалидные данные: пустой заголовок, прошедшая дата дедлайна,
     несуществующий `project_id`.

2. **`track_time(task_id: int, hours: float) -> float`**
   - Добавляет отработанные часы к задаче с `task_id`.
   - Проверить корректность при разных входных значениях: 0 часов, отрицательное число,
     очень большие числа.
   - Можно мокать доступ к базе данных для обновления задачи.

3. **`calculate_invoice(hours: float, rate: float, currency: str) -> float`**
   - Рассчитывает сумму счёта на основе потраченных часов и почасовой ставки с учётом
     валюты.
   - Тестировать граничные случаи: 0 часов, нулевая ставка, непредусмотренная валюта.
   - Проверить корректность округления результата.

4. **`check_project_deadline(project_id: int) -> bool`**
   - Возвращает `True`, если проект ещё не просрочен, и `False`, если дедлайн пройден.
   - Определить, как функция получает данные о проекте (мокать базу или репозиторий).
   - Проверить, что функция корректно обрабатывает случай, когда дедлайн сегодня /
     завтра / был вчера.

5. **`send_task_notification(email: str, task_info: dict) -> bool`**
   - Отправляет уведомление пользователю о состоянии задачи (создана, завершена,
     просрочена).
   - Мокать сервис отправки писем.
   - Проверить обработку ошибок: невалидный email, сбой SMTP.

## Формат сдачи и отправка задания

- Собрать код тестов в **одном файле** в формате `.py`.
- Добавить README-файл *(опционально)*.
- Подписать файл: **`test_название_сервиса_ФИО.py`**.

## Критерии оценивания

| Критерии оценивания для одной функции | Баллы |
|---|---|
| Реализована функция, описаны тесты. Тесты выполняют необходимые проверки | 2 |
| Логика проверки в тестах реализована корректно, но тесты не запускаются | 1 |
| Функция и тесты не реализованы или реализованы не полностью | 0 |

**Блокирующий критерий. Несоответствие форматов сдачи**

| Условие | Результат |
|---|---|
| На проверку отправлены не все файлы, нет части файлов; **или** приложен файл другого формата, отличного от описанных в разделе «Формат сдачи и отправка задания»; **или** другие отклонения в форматах / количестве / названиях файлов на сдачу | 0 баллов за решение всего задания |

- **Максимальный балл за задание:** 10.
- **Как проверяется:** преподаватель проверит задание в течение недели после дедлайна.
